Weboldal vagy webalkalmazás?

A weboldal és a webalkalmazás közötti legfontosabb különbség az, hogy mire használja a látogató.

  • Weboldal: elsősorban információt közöl, bemutat valamit, vagy segít megtalálni a keresett információt.
  • Webalkalmazás: lehetővé teszi, hogy a felhasználó műveleteket végezzen, adatokat kezeljen, és interakcióba lépjen a rendszerrel.

A két kategória nem válik el élesen egymástól. Egy weboldal is lehet interaktív, és egy webalkalmazás is tartalmazhat információs oldalakat.

1. Weboldal

Egy hagyományos weboldal például egy vállalkozás vagy egy webfejlesztő portfóliója.

Tipikus funkciói:

  • Bemutatkozás és szolgáltatások ismertetése.
  • Referenciák és projektek bemutatása.
  • Kapcsolatfelvételi lehetőség.
  • Blogcikkek és információk megjelenítése.

Példa a portfóliódra

A látogató megnyitja az oldaladat, megismeri a munkáidat, elolvassa a bemutatkozásodat, majd felveszi veled a kapcsolatot. Az oldal elsődleges célja az információátadás és a bizalomépítés.

2. Webalkalmazás

A webalkalmazás valamilyen feladat elvégzését teszi lehetővé.

Tipikus funkciói:

  • Felhasználói fiókok kezelése.
  • Adatok létrehozása, módosítása és törlése.
  • Keresés és szűrés.
  • Adatok mentése és későbbi visszatöltése.
  • Automatikus számítások.
  • Személyre szabott tartalom és értesítések.

Példa: háztartási alkalmazás

A háztartás tagjai rögzítik az otthon található termékeket, megadják a tárolási helyüket, és közösen kezelik a bevásárlólistát.

A rendszer összehasonlíthatja a receptek hozzávalóit a meglévő készlettel, majd összeállíthatja a hiányzó termékek listáját.

3. Mi a technikai különbség?

Nem a használt programozási nyelv dönti el, hogy weboldalt vagy webalkalmazást készítesz. Mindkettő készülhet HTML, CSS és JavaScript használatával.

Szempont Weboldal Webalkalmazás
Elsődleges cél Információ közlése Feladatok elvégzése
HTML és CSS Tartalom és megjelenés Felület és megjelenés
JavaScript Interaktív elemek Interakciók és adatfeldolgozás
Backend Nem feltétlenül szükséges Gyakran szükséges
Adatbázis Nem feltétlenül szükséges Gyakran szükséges
Bejelentkezés Általában nem szükséges Gyakori

Ezek jellemző különbségek, nem kötelező szabályok. Egy weboldal is használhat adatbázist, és egy egyszerű webalkalmazás backend nélkül is működhet.

4. Hogyan épül fel egy weboldal?

Egy egyszerű, statikus weboldal esetében a böngésző megkapja a HTML-, CSS- és esetleg JavaScript-fájlokat, majd megjeleníti a tartalmat.

Böngésző
↓
HTML + CSS + JavaScript
↓
A weboldal megjelenik

Ehhez nem feltétlenül szükséges adatbázis vagy saját backend.

5. Hogyan épülhet fel egy webalkalmazás?

Felhasználó
↓
Frontend
HTML + CSS + JavaScript
↓
Backend / API
↓
Adatbázis

Frontend

A felület, amelyet a felhasználó lát és kezel. Ide tartoznak a gombok, űrlapok, táblázatok és az interaktív elemek.

Backend

A szerveren futó program, amely például ellenőrzi a jogosultságokat, feldolgozza a kéréseket és kezeli az üzleti logikát.

API

Meghatározott kommunikációs felület, amelyen keresztül a frontend kéréseket küldhet a backendnek.

Adatbázis

Itt tárolhatók tartósan a felhasználók, termékek, receptek és egyéb adatok.

Ez a felépítés nem minden esetben szükséges. Egy egyszerű alkalmazás tárolhat adatokat például a böngésző localStorage tárhelyén is. Ez azonban önmagában nem biztosít közös, több eszközről elérhető adattárolást.

6. Hol helyezkedik el ebben a JavaScript?

Technológia Feladat Példa
HTML Szerkezet A bevásárlólista elemei
CSS Megjelenés A lista elrendezése és színei
JavaScript Viselkedés Új termék hozzáadása
Backend Szerveroldali feldolgozás Jogosultságok ellenőrzése
Adatbázis Tartós adattárolás A bevásárlólista mentése

JavaScripttel például megoldhatod, hogy a felhasználó új terméket adjon a listához, vagy kipipálja a már megvásárolt termékeket. Ezzel már létrehozhatsz egy egyszerű, működő webalkalmazást.

Ha azt szeretnéd, hogy a háztartás más tagjai is lássák a változtatásokat a saját telefonjukon, közös adattárolásra és rendszerint szerveroldali vagy felhőalapú szolgáltatásra is szükséged lesz.

Fontos tanulság: a webalkalmazás nem attól alkalmazás, hogy bonyolult technológiát használ, hanem attól, hogy valamilyen feladat elvégzésére szolgál.

7. Hogyan építsd fel a tanulásodat?

Első lépés: weboldal készítése

  • Szemantikus HTML.
  • CSS, Flexbox és Grid.
  • Reszponzív tervezés.
  • Bootstrap.
  • Hozzáférhető navigáció és űrlapok.

Második lépés: JavaScript-alapú interaktivitás

  • Eseménykezelés.
  • A DOM módosítása.
  • Űrlapadatok feldolgozása.
  • Tömbök és objektumok használata.
  • Adatok tárolása a böngészőben.

Harmadik lépés: teljesebb webalkalmazás

  • API-k használata.
  • Backend működése.
  • Adatbázis-kezelés.
  • Felhasználói hitelesítés és jogosultságok.
  • Több felhasználó közötti adatmegosztás.

Nem szükséges mindezt egyszerre megtanulnod. A korábbi lépésekre építve fokozatosan növelheted a projektjeid összetettségét.

Ellenőrző kérdés

Képzeld el, hogy elkészítesz egy időjárási felületet. A látogató látja Koppenhága aktuális hőmérsékletét, a következő órák előrejelzését és a csapadék mennyiségét. Az adatokat egy időjárási API biztosítja.

Szerinted ez weboldal vagy webalkalmazás? Gondold végig, hogy a felület csupán megjeleníti az adatokat, vagy a felhasználó különböző műveleteket is végezhet rajta.
