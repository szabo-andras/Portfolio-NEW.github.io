Google Sheets-Based Travel Planning and Expense Tracking Automation

My latest personal project was a Google Sheets-based travel planning and expense tracking system for a three-month trip that we organized ourselves. My goal was to manage the planning and financial tasks for a trip spanning multiple countries and cities in one place.

For expense tracking, I primarily used the following tools:

  • Google Forms
  • formulas
  • automatic currency conversion,
  • drop-down lists
  • summaries
This allowed me to record expenses in different currencies, track the daily budget, and simplify expense reconciliation afterward.

I also extended the system with Google Apps Script, with support from ChatGPT. The automations routed expenses submitted through the form to the worksheet for the relevant city and generated worksheets for each city’s daily itinerary and accommodation details based on the route plan. I based these on a worksheet structure I had created manually earlier, then refined the generated sheets by hand as needed.

I started with my own practical needs, defined how the system should work, and used AI to develop an automated solution that reduced repetitive manual tasks. This experience strengthened my interest in technology, process automation, and building digital tools tailored to specific needs.

The system helped me manage sales-related information in a structured way, review customer and contract details more easily, and monitor revenue.

Rudolph Logistik Kft. – Employee Database – MS Access

As early as 2007, I was interested in how technology could make workflows more efficient.

At Rudolph Logistik Kft. in Győr, some worksheets in the Excel file had become so full over the years that new columns could no longer be added. This became a serious issue when a new employee benefits system was introduced.

Instead of managing the data in one place, the employee database had to be kept up to date across two Excel files. High staff turnover led to frequent discrepancies between them.

Using the existing Excel file as a starting point, I built a Microsoft Access database with forms to manage HR data for approximately 1,100 employees. I also created queries and reports for tasks that had previously taken several hours of manual filtering at the end of each month.

The system tracked salaries, roles, education, training, and employee benefits. This project was an early example of turning existing data into a more structured and manageable system.

Building a website

A website primarily shares information and presents a person, business, service, or project.

What is it used for?

  • Introducing a person or explaining services.
  • Showcasing work and projects.
  • Providing a way to get in touch.
  • Publishing news, articles, and other useful information.

Example: a family guesthouse

Visitors learn about the accommodation, browse photos, and find information about its services and prices. The website presents the guesthouse and helps visitors contact its owners.

What is it made of?

  • HTML: the page content and structure.
  • CSS: the layout and visual presentation.
  • JavaScript: interactive features such as menus and forms.

A simple static website does not necessarily need a backend or database. The browser displays the content from HTML, CSS, and JavaScript files.

How do we get started?

  1. We build the foundations of the website with semantic HTML.
  2. We use CSS and/or Bootstrap to create a responsive layout.
  3. We add navigation, an introduction, and a way to get in touch.

  4. We add JavaScript interactions, for example, to let visitors:

    • open and close the mobile navigation menu;
    • expand answers to frequently asked questions;
    • view gallery images at a larger size;
    • search or filter projects by category;
    • get feedback when a form is completed and submitted;
    • switch between light and dark themes.

Building a web application

A web application lets users complete tasks, manage data, and interact with a system.

Typical features:

  • Managing user accounts.
  • Creating, updating, and deleting data.
  • Searching and filtering.
  • Saving data and loading it again later.
  • Automated calculations.
  • Personalized content and notifications.

Example: a household app

Household members record the items they have at home, specify where they are stored, and manage a shared shopping list.

The system can compare recipe ingredients with the items already in stock and create a list of anything that is missing.

How might a web application be structured?

↓

Frontend

The interface that users see and interact with, including buttons, forms, tables, and other interactive elements.

Backend

Software running on a server that can check permissions, process requests, and handle business logic.

API

A defined interface through which the frontend can send requests to the backend.

Database

A database stores users, products, recipes, and other data persistently.

This architecture is not always necessary. A simple application can store data in the browser, for example, using localStorage for local storage. However, this alone does not provide shared storage that can be accessed from multiple devices.

With JavaScript, for example, you can let users add items to a list or check off items they have purchased. That is enough to create a simple, working web application.

If you want other household members to see changes on their own phones, you will also need shared data storage, usually through a server-side or cloud service.

Key takeaway: A web application is defined not by how complex its technology is, but by the task it enables people to complete.
