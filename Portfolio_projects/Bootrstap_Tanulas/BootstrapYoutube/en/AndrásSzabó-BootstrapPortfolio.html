Portfolio Projects

Some of the major projects I built before I began learning web development:

Google Sheets-Based Travel Planning and Expense Tracking Automation

My latest personal project was a travel planning and expense tracking system built for a three-month trip that we organized ourselves. It was based on Google Sheets-based travel planning and expense tracking system. My goal was to manage the planning and financial tasks for a trip spanning multiple countries and cities in one place.

For expense tracking, I primarily used the following tools:

  • Google Forms
  • formulas
  • automatic currency conversion,
  • drop-down lists
  • summaries
This allowed me to record expenses in different currencies, track the daily budget, and simplify expense reconciliation afterward.

I also extended the system with Google Apps Script, with support from ChatGPT. The automations routed expenses submitted through the form to the worksheet for the relevant city and generated worksheets for each city’s daily itinerary and accommodation details based on the route plan. I based these on a worksheet structure I had created manually earlier, then refined the generated sheets by hand as needed.

I started with my own practical needs, defined how the system should work, and used AI to develop an automated solution that reduced repetitive manual tasks. This experience strengthened my interest in technology, process automation, and building digital tools tailored to specific needs.

Sales Tracker and Customer Database – MS Excel, MS Access

To support my sales work, I created an Excel-based tracking system that brought sales contracts, customer details, and revenue tracking together in one place.

The system helped me manage sales-related information in a structured way, review customer and contract details more easily, and monitor revenue.

I designed the solution around my own workflows and used Excel to create a practical tool that supported day-to-day work and organized business information.

Rudolph Logistik Kft. – Employee Database – MS Access

As early as 2007, I was interested in how technology could make workflows more efficient.

At Rudolph Logistik Kft. in Győr, some worksheets in the Excel file had become so full over the years that new columns could no longer be added. This became a serious issue when a new employee benefits system was introduced.

Instead of managing the data in one place, the employee database had to be kept up to date across two Excel files. High staff turnover led to frequent discrepancies between them.

Using the existing Excel file as a starting point, I built a Microsoft Access database with forms to manage HR data for approximately 1,100 employees. I also created queries and reports for tasks that had previously taken several hours of manual filtering at the end of each month.

The system tracked salaries, roles, education, training, and employee benefits. This project was an early example of turning existing data into a more structured and manageable system.

Website or web application?

The key difference between a website and a web application is what visitors use it to do.

  • Website: primarily shares information, presents something, or helps visitors find what they are looking for.
  • Web application: allows users to perform actions, manage data, and interact with the system.

The two categories are not mutually exclusive. A website can be interactive, and a web application can also include informational pages.

1. Website

A traditional website might be a business website or a web developer’s portfolio.

Typical features:

  • An introduction and information about services.
  • Showcasing work and projects.
  • A way to get in touch.
  • Publishing articles and other information.

Example: your portfolio

A visitor opens your site, explores your work, reads your introduction, and then contacts you. The site’s primary purpose is to share information and build trust.

2. Web application

A web application enables users to complete a task.

Typical features:

  • Managing user accounts.
  • Creating, updating, and deleting data.
  • Searching and filtering.
  • Saving data and loading it again later.
  • Automated calculations.
  • Personalized content and notifications.

Example: a household app

Household members record the items they have at home, specify where they are stored, and manage a shared shopping list.

The system can compare recipe ingredients with the items already in stock and create a list of anything that is missing.

3. What is the technical difference?

The programming language you use does not determine whether you are building a website or a web application. Both can be built with HTML, CSS, and JavaScript.

Aspect Website Web application
Primary purpose Sharing information Completing tasks
HTML and CSS Content and presentation Interface and presentation
JavaScript Interactive elements Interactions and data processing
Backend Not necessarily required Often required
Database Not necessarily required Often required
Sign-in Usually not required Common

These are typical differences, not strict rules. A website can use a database, and a simple web application can work without a backend.

4. How is a website structured?

For a simple static website, the browser receives the HTML, CSS, and possibly JavaScript files, then displays the content.

Browser
↓
HTML + CSS + JavaScript
↓
The website is displayed

A database or custom backend is not necessarily needed for this.

5. How might a web application be structured?

User
↓
Frontend
HTML + CSS + JavaScript
↓
Backend / API
↓
Database

Frontend

The interface that users see and interact with, including buttons, forms, tables, and other interactive elements.

Backend

Software running on a server that can check permissions, process requests, and handle business logic.

API

A defined interface through which the frontend can send requests to the backend.

Database

A database stores users, products, recipes, and other data persistently.

This architecture is not always necessary. A simple application can store data in the browser, for example, using localStorage for local storage. However, this alone does not provide shared storage that can be accessed from multiple devices.

6. What role does JavaScript play?

Technology Role Example
HTML Structure Shopping list items
CSS Presentation The list’s layout and colors
JavaScript Behavior Adding a new item
Backend Server-side processing Checking permissions
Database Persistent data storage Saving the shopping list

With JavaScript, for example, you can let users add items to a list or check off items they have purchased. That is enough to create a simple, working web application.

If you want other household members to see changes on their own phones, you will also need shared data storage, usually through a server-side or cloud service.

Key takeaway: A web application is defined not by how complex its technology is, but by the task it enables people to complete.

7. How to structure your learning

Step 1: Build a website

  • Semantic HTML.
  • CSS, Flexbox, and Grid.
  • Responsive design.
  • Bootstrap.
  • Accessible navigation and forms.

Step 2: Add JavaScript interactivity

  • Event handling.
  • Manipulating the DOM.
  • Processing form data.
  • Working with arrays and objects.
  • Storing data in the browser.

Step 3: Build a fuller web application

  • Using APIs.
  • How a backend works.
  • Database management.
  • User authentication and permissions.
  • Sharing data between users.

You do not need to learn everything at once. Build on each step and gradually increase the complexity of your projects.

Quick check

Imagine building a weather page that shows the current temperature in Copenhagen, the forecast for the next few hours, and precipitation levels. The data comes from a weather API.

Would you consider this a website or a web application? Consider whether the page only displays information or also lets users perform actions.
